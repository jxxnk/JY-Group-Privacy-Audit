# JY Group Privacy Audit

## 가상 그룹사 개인정보 보호 관리체계 진단 및 ISMS-P 사전심사 프로젝트

> 한 계열사의 취약점이 그룹 전체의 개인정보 사고로 번지지 않도록

이 저장소는 HD현대그룹 계열사 개인정보 유출사고에서 확인된 문제를 출발점으로 삼아, 가상의 그룹사·자회사·수탁사가 함께 사용하는 개인정보 처리환경을 진단하고 개선하는 100시간 규모의 개인 보안 컨설팅 프로젝트를 기록합니다.

프로젝트는 단순한 취약점 스캐너 제작이나 웹 모의해킹을 목표로 하지 않습니다. 실제 개인정보 보호 컨설턴트가 수행하는 업무처럼 다음 과정을 하나의 흐름으로 재현합니다.

1. 사건과 제도 변화를 조사합니다.
2. 가상 고객사와 개인정보 처리환경을 설계합니다.
3. 그룹사 전체의 개인정보 처리업무와 자산을 파악합니다.
4. 본사·자회사·수탁사 사이의 개인정보 흐름과 시스템 연결을 확인합니다.
5. 개인정보 보호법, ISMS-P, ISO/IEC 27701:2025를 기준으로 사전심사를 수행합니다.
6. 주통기 가이드는 서버·DB·네트워크 기술점검에만 제한해서 사용합니다.
7. 기술 증적을 자동으로 수집하되, 최종 판단은 컨설턴트가 수행합니다.
8. 발견한 문제에 대한 개선안을 제시하고 같은 기준으로 재점검합니다.
9. 실무진 보고서와 CPO·경영진 보고자료를 각각 작성합니다.

## 1. 프로젝트를 시작한 배경

2026년 8월 개인정보보호위원회가 공개한 HD현대그룹 계열사 사고에서는 HD한국조선해양의 모바일 기기 관리 서버에 존재한 파일 업로드 취약점이 최초 침입 경로로 이용됐습니다. 해당 서버는 업무상 연결할 필요가 없었던 HD건설기계의 내부 업무시스템과 통신할 수 있었습니다. 공격자는 한 계열사의 취약한 서버에서 다른 계열사로 이동했고, 임직원과 협력사 직원 9,503명의 개인정보가 유출됐습니다.

- 공식 자료: [개인정보위, 안전조치 의무를 위반한 HD현대그룹 소속 2개 사업자 제재](https://www.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=&nttId=12414)

이 사고에서 주목한 부분은 파일 업로드 취약점 자체만이 아닙니다. 취약한 서버와 다른 계열사의 개인정보처리시스템 사이에 불필요한 연결이 존재했고, 각 회사가 자신의 시스템만 개별적으로 관리하면서 그룹사 전체 연결관계에서 책임 공백이 생겼다는 점입니다.

이 프로젝트는 다음 질문에서 시작했습니다.

> 각 계열사가 자신의 서버와 개인정보 처리방침만 따로 점검한다면, 계열사 사이의 불필요한 연결과 개인정보 처리 책임의 공백은 누가 발견해야 하는가?

> 내가 그룹사 개인정보 보호 컨설턴트라면 본사, 자회사, 수탁사의 개인정보 흐름을 어떻게 파악하고, 발견한 위험을 어떤 기준으로 평가하고, 경영진에게 어떤 개선안을 제시할 것인가?

이 질문에 직접 답하기 위해 가상의 JY그룹을 만들고, 그룹사 개인정보 관리체계 진단부터 기술 증적수집, 개선 및 재점검까지 수행합니다.

## 2. 프로젝트가 다루는 보안의 현재와 미래

최근 개인정보 사고는 단일 웹서버의 취약점만으로 설명하기 어렵습니다. 계열사, 전문 수탁사, 클라우드 사업자, 시스템 공급사와 외부 API가 연결되면서 한 조직의 취약점이 다른 조직으로 확산될 가능성이 커졌습니다. 따라서 앞으로의 개인정보 보호 컨설팅은 개별 시스템의 설정뿐 아니라 다음 내용을 함께 확인해야 합니다.

- 개인정보가 어느 조직과 시스템을 이동하는지
- 각 조직이 개인정보처리자, 수탁자 또는 제3자 중 어떤 역할을 맡는지
- 업무상 필요하지 않은 연결이 남아 있는지
- 공동계정과 협력사 계정이 과도한 권한을 보유하는지
- 처리방침, 계약서, 내부 관리대장과 실제 시스템 운영이 일치하는지
- CPO가 위험과 개선 현황을 경영진에게 보고할 수 있는지
- 사고가 발생하기 전에 위험을 발견하고 개선하는 절차가 운영되는지

2026년 개정 개인정보 보호법은 CEO와 CPO의 책임을 강화하고, 주요 기업·기관의 ISMS-P 인증 의무화를 예고했습니다. 프로젝트에서는 현재 시행 중인 요구사항만 보는 것이 아니라 앞으로 강화될 책임과 사전예방 중심 정책도 반영합니다.

- 공식 자료: [개인정보 유출사고 예방을 위해 개인정보 보호 책임·관리체계 강화](https://m.pipc.go.kr/np/cop/bbs/selectBoardArticle.do?bbsId=BS074&mCode=C020010000&nttId=11865)

## 3. 가상 고객사

### JY홀딩스

그룹 공통 개인정보 보호 정책과 IT 인프라를 담당합니다.

- 그룹웨어
- 모바일 기기 관리 서버
- 통합계정 관리
- 그룹 공통 로그 서버
- 그룹 개인정보 보호 규정
- 자회사 개인정보 보호수준 점검

### JY산업

임직원과 협력사 개인정보를 처리합니다.

- 인사시스템
- 급여·근태정보
- 협력사 출입관리
- 임직원 교육정보
- 협력사 담당자 정보

### JY서비스

회원과 고객상담 정보를 처리합니다.

- 회원관리시스템
- 주문·환불 시스템
- 고객관리시스템
- 상담이력
- 마케팅 수신 동의정보

### 외부 고객센터

JY서비스의 고객상담 업무를 위탁받습니다.

- 고객 성명과 연락처 조회
- 주문·배송정보 조회
- 상담이력 작성
- 상담 녹취파일 보관

프로젝트에서는 Faker 등으로 생성한 가상 데이터만 사용합니다. 실제 개인정보, 실제 기업 내부자료와 외부 시스템은 점검하지 않습니다.

## 4. 프로젝트의 핵심 문제 상황

가상 환경에는 실제 컨설팅에서 발견할 수 있는 문제를 의도적으로 구성합니다.

### 그룹사 사이의 불필요한 연결

- JY홀딩스 관리 서버에서 JY산업 인사시스템으로 접근 가능
- 관리 서버에서 JY서비스 고객 DB 구간으로 접근 가능
- 업무 목적보다 넓은 포트 범위 허용
- 시스템 연결 승인과 정기 검토 기록 부재

### 계정 및 접근권한 문제

- 계열사 공동 관리자 계정 사용
- 퇴사한 협력사 계정 미삭제
- 장기간 사용하지 않은 관리자 계정 유지
- 수탁사 계정의 접속 가능 시간 미제한
- 개인정보 조회권한 과다 부여

### 시스템 보안 설정 문제

- 불필요한 서비스와 포트 활성화
- 주요 파일 권한 과다
- 보안 패치 미적용
- DB 원격접속 범위 과다
- 접속기록 미수집 또는 보관기간 부족
- 백업파일 접근통제 미흡

### 관리체계 문제

- 본사와 자회사의 개인정보 자산목록 불일치
- 처리방침과 실제 수집 항목 또는 보유기간 불일치
- 수탁사 점검 결과와 후속조치 기록 부재
- 계열사 간 개인정보 제공 관계 불명확
- 신규 시스템 연결 전 개인정보 위험평가 부재
- CPO의 경영진 보고 증적 부족
- 침해사고 대응훈련과 개선 기록 부재

## 5. 프로젝트 목표

1. 그룹사 전체의 개인정보 처리업무와 관련 자산을 식별합니다.
2. 본사·자회사·수탁사 사이의 개인정보 흐름과 책임을 구분합니다.
3. 계열사 사이의 불필요한 시스템 연결과 과도한 접근권한을 확인합니다.
4. 개인정보 보호법, ISMS-P와 ISO/IEC 27701:2025를 기준으로 준비 수준을 진단합니다.
5. 서버·DB·네트워크의 기술 증적을 자동으로 수집합니다.
6. 자동수집 결과를 법률과 인증기준에 연결하되 최종 판단은 사람이 수행합니다.
7. 단기·중기·장기 개선계획을 작성합니다.
8. 개선 전후 결과를 동일한 기준으로 비교합니다.
9. 기술 담당자와 경영진이 각각 이해할 수 있는 보고서를 작성합니다.

## 8. 증적 자동수집 원칙

자동수집 기능은 프로젝트 전체의 보조수단입니다. 도구가 인증 충족 여부를 직접 판정하거나 컨설턴트의 결정을 대체하지 않습니다.

각 자동수집 결과에는 다음 정보가 포함돼야 합니다.

- 점검 대상 자산
- 수집 일시
- 수집한 설정 또는 명령 결과
- 현재 값과 기대 기준
- 자동수집 상태
- 관련 개인정보 보호법 조항
- 관련 ISMS-P 항목
- 관련 주통기 기술 항목
- 담당자가 확인해야 할 업무 목적과 예외 승인
- 최종 판단과 판단 근거

자동 상태값은 다음 세 가지로 제한합니다.

- `확인 필요`
- `개선 후보`
- `자동수집 불가`

최종 상태값인 양호, 일부 충족, 미흡, 취약과 해당 없음은 담당자가 증적과 업무 맥락을 확인한 뒤 결정합니다.

## 14. 면접용 프로젝트 설명

> HD현대그룹 계열사 개인정보 유출사고를 보면서 파일 업로드 취약점 자체보다 업무상 불필요한 계열사 간 시스템 연결이 사고 범위를 키웠다는 점에 주목했습니다. 각 계열사가 자신의 시스템만 개별적으로 점검하면 그룹사 사이의 개인정보 흐름과 연결 관계에서 책임 공백이 생길 수 있다고 생각했습니다.

> 그래서 가상의 그룹사와 자회사, 수탁사 환경을 구성하고 개인정보 처리현황, 위탁 관계, 시스템 연결, 계정과 접근권한을 함께 진단했습니다. 개인정보 보호법과 ISMS-P를 중심으로 사전심사를 수행했고, ISO/IEC 27701:2025의 개인정보 관리체계 원칙을 참고했습니다. 주통기 가이드는 서버와 DB, 네트워크의 기술 설정을 확인하는 데만 사용했습니다.

> 또한 심사 때마다 증적을 수작업으로 준비하는 문제를 줄이기 위해 계정, 포트, 방화벽, 로그와 패치 상태를 자동으로 수집하는 기능을 만들었습니다. 자동수집 결과가 적합 여부를 직접 판단하지 않도록 했고, 업무 목적과 예외 승인 여부를 확인한 뒤 최종 판단하도록 설계했습니다.

> 마지막으로 불필요한 계열사 연결 차단, 자회사·수탁사 권한관리, CPO 보고체계와 그룹 공통 개인정보 관리 절차를 개선안으로 제시하고, 같은 기준으로 재점검해서 개선 결과까지 확인했습니다.

## 15. 프로젝트의 핵심 차별점

이 프로젝트는 다음 이유로 기존 웹 취약점 자동화 및 AWS 보안 프로젝트와 구분됩니다.

- 공격 성공 자체보다 개인정보 사고가 확산된 조직적 원인을 분석합니다.
- 관리체계, 법률, 인증, 자회사·수탁사와 기술 설정을 함께 다룹니다.
- 스크립트가 중심이 아니라 컨설턴트의 판단을 뒷받침하는 증적수집 도구를 만듭니다.
- 발견에서 끝나지 않고 개선과 재점검까지 수행합니다.
- CPO와 경영진에게 보고하는 책임성과 미래 제도 변화를 반영합니다.
- Git 이력으로 프로젝트의 의도, 판단, 수정과 결과를 모두 추적할 수 있습니다.
