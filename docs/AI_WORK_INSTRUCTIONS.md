# GPT 및 AI 작업 지침

## 1. 이 문서의 역할

이 저장소에서 작업하는 GPT·코딩 에이전트·생성형 AI는 작업을 시작하기 전에 이 문서를 읽어야 한다. 목표는 대화가 바뀌어도 프로젝트의 서사, 범위, 안전기준과 결정이 유지되게 하는 것이다. AI는 보조 연구자·문서작성자·개발자 역할을 하며 법률·인증 적합성의 최종판정자가 아니다.

## 2. 첫 작업 전 필독 순서

1. `START_HERE_NEW_CHAT.md`: 새 환경 및 새 채팅 시작방법
2. `PROJECT_STATE.md`: 현재 진행단계와 바로 다음 작업
3. `README.md`: 프로젝트의 배경과 전체 의도
4. `AGENTS.md`: 저장소 내 AI 공통규칙
5. `docs/PROJECT_MASTER_PLAN.md`: 수행범위와 단계
6. `docs/DECISION_LOG.md`: 확정된 결정과 보류사항
7. 현재 작업과 관련된 Issue 및 PR
8. `docs/CONTROL_BASELINE.md`: 적용기준과 해석 한계
9. `docs/GIT_WORKFLOW.md`: 브랜치·검증·병합 방식
10. `docs/DELIVERABLES_AND_DOD.md`: 산출물과 완료조건
11. 관련 폴더의 `README.md`

문서가 충돌하면 최신 승인된 의사결정 기록, 프로젝트 통합 수행계획, 루트 README, 하위 문서 순으로 우선한다. 법령·공식기준은 항상 최신 공식 원문이 우선하며 문서가 낡았으면 변경을 제안한다.

## 3. AI에게 제공할 작업 지시 형식

사용자는 아래 형식으로 업무를 지시할 수 있다.

```text
목표:
대상 Issue/브랜치:
읽어야 할 파일:
변경 허용 범위:
필수 산출물:
완료조건:
금지사항 또는 보안제약:
검증 명령:
```

필드가 일부 없으면 저장소 문서와 Issue에서 먼저 확인한다. 결과가 크게 달라지는 정보만 사용자에게 질문한다.

## 4. 작업 시작 시 AI 행동

- 현재 브랜치와 변경상태를 확인한다.
- 기존 사용자 변경을 보존한다.
- 해당 작업의 Issue, 범위와 완료조건을 짧게 재확인한다.
- 법·정책·버전·사건처럼 변할 수 있는 사실은 공식 출처에서 최신성을 확인한다.
- 코드 변경이면 기존 테스트와 출력 스키마를 확인한다.
- 문서 변경이면 관련 링크와 상위 문서의 일관성을 확인한다.
- 필요한 파일만 변경하고 무관한 정리를 섞지 않는다.

## 5. 절대 유지할 프로젝트 원칙

1. 프로젝트의 중심은 개인정보 보호 컨설팅이며 취약점 공격도구 제작이 아니다.
2. 개인정보 보호법과 ISMS-P가 핵심 기준이다.
3. ISO/IEC 27701은 합법적으로 접근 가능한 범위의 원칙·공개정보만 사용한다.
4. 주통기 가이드는 서버·DB·네트워크 기술점검 방법에만 적용한다.
5. JY그룹과 모든 개인정보는 가상·합성 데이터다.
6. 자동화는 증적을 모으고 정규화하지만 적합성의 최종판단은 사람이 한다.
7. 결과 상태는 자동 상태와 컨설턴트 상태를 분리한다.
8. 개선 전과 개선 후를 동일한 기준으로 비교한다.
9. 기술보고와 경영진 보고는 독자와 목적을 구분한다.
10. 실제 개인정보, 인증정보, ISO 원문과 공개 부적절 원본증적을 Git에 넣지 않는다.

## 6. 허용되는 자동 상태와 최종 상태

자동수집기는 다음 상태만 출력한다.

- `확인 필요`
- `개선 후보`
- `자동수집 불가`

다음 상태는 담당자가 증적과 업무 맥락을 검토한 후에만 기록한다.

- `양호`
- `일부 충족`
- `미흡`
- `취약`
- `해당 없음`

AI가 최종 상태를 제안할 수는 있지만 `AI 제안`, 근거, 불확실성과 필요한 사람의 확인을 표시해야 한다.

## 7. 연구 및 출처 규칙

- 법령은 국가법령정보센터 및 개인정보보호위원회 공식자료를 우선한다.
- ISMS-P는 인증제도 공식 홈페이지와 KISA 자료를 우선한다.
- 사고사실은 규제기관·수사기관·기업 공식 발표를 우선한다.
- 기술기준은 KISA 및 공급자 공식문서를 우선한다.
- 블로그·언론은 맥락 파악용이며 핵심 결론의 유일한 근거로 쓰지 않는다.
- 출처 URL, 문서명, 발행기관, 게시일/시행일, 확인일과 적용범위를 남긴다.
- 직접 확인한 사실, 출처로부터의 합리적 해석, 프로젝트 제안을 명확히 구분한다.
- 최신성이 필요한 조사에는 조사 기준일을 적는다.

## 8. 법률·인증 표현 규칙

AI는 다음과 같이 표현한다.

- `개인정보 보호법 제29조 안전조치 의무 관련 확인사항`
- `ISMS-P 사전진단 결과`
- `ISO/IEC 27701:2025 공개정보 및 관리체계 원칙 참고`
- `주통기 가이드 기반 기술 설정 확인`

다음 표현은 근거와 자격 없이 사용하지 않는다.

- `법률 준수 보장`
- `공식 인증 통과`
- `ISO 27701 완전 준수`
- `주요정보통신기반시설 판정`
- `AI가 부적합으로 확정`

법령의 적용 여부가 조직 규모·업종·시행일·사실관계에 따라 달라지면 조건부로 작성하고 전문가 확인 필요성을 남긴다.

## 9. 코드 작성 규칙

- Python을 기본 오케스트레이션 언어로 사용하고 OS별 읽기 전용 수집은 Bash/PowerShell을 허용한다.
- 모듈은 `수집 → 정규화 → 마스킹 → 평가보조 → 출력`으로 분리한다.
- 모든 출력은 자산 ID, 수집시각, 수집기 버전, 명령/방법, 원본 참조, 해시와 오류를 포함한다.
- 명령 실패를 양호로 처리하지 않는다.
- 권한 부족, 미지원 OS, 시간초과와 부분수집을 구분한다.
- 비밀번호·해시·토큰·개인정보 값은 수집하지 않거나 즉시 마스킹한다.
- 원격 점검은 명시된 실습 대상과 승인된 계정에만 수행한다.
- 파괴적 명령, 무단 스캔과 외부 공격 자동화는 작성·실행하지 않는다.
- 새 기능에는 정상·오류·마스킹 테스트를 추가한다.

## 10. 증적 취급 규칙

증적은 `evidence/before`, `evidence/after`, `evidence/sanitized`로 구분한다. Git에는 공개 가능한 합성·마스킹 증적만 둔다. 원본 증적이 필요하면 저장소 밖 암호화 위치에 두고 Git에는 해시와 보관위치 식별자만 기록한다.

증적 파일명 예시:

```text
EV-HOLD-MDM-ACCT-001_2026-09-12T103000Z.sanitized.json
```

AI가 증적 내용을 요약할 때 원본에 없는 사실을 보충하지 않는다. 누락·실패·불확실성을 그대로 기록한다.

## 11. 문서 갱신 규칙

다음 변경은 코드만 바꾸고 끝내지 않는다.

| 변경 | 함께 갱신할 문서 |
|---|---|
| 범위·조직·가정 | README, 통합계획, 의사결정 기록 |
| 적용 법령·기준 | 통제기준, 출처대장, 관련 매핑 |
| 출력 스키마 | collector README, 테스트, 샘플 |
| 위험평가 방법 | 통합계획, 산출물 완료조건 |
| 브랜치·CI 정책 | Git 흐름, CONTRIBUTING |
| 최종 결과 | README 완료상태, 보고서, Release notes |

중요 판단은 `docs/DECISION_LOG.md`에 `결정/이유/대안/영향/날짜`로 남긴다. 아직 결정되지 않은 항목을 확정 사실처럼 쓰지 않는다.

## 12. 결과 보고 형식

AI의 작업 완료 보고에는 다음을 포함한다.

1. 달성한 결과
2. 변경한 파일
3. 검증한 방법과 결과
4. 남은 한계·불확실성
5. 다음에 이어갈 Issue 또는 브랜치

단순히 `완료`라고 하지 않는다. 테스트를 실행하지 못했으면 그 이유와 사람이 실행할 명령을 제공한다.

## 13. 금지사항

- 실제 기업을 대상으로 허가 없는 탐색·스캔·공격
- 실제 개인정보 또는 고객 증적 생성·업로드
- 비밀값을 예시라는 이유로 하드코딩
- 출처를 확인하지 않은 법률·사건 수치 확정
- ISO 유료 원문 복제 및 재배포
- 자동수집 결과를 공식 심사판정으로 표현
- 테스트 실패를 숨기거나 검증 단계를 생략
- 기존 사용자 변경을 임의로 되돌리기
- README의 서사와 무관한 기능 확장

## 14. 작업 종료 체크리스트

- [ ] Issue 범위와 완료조건을 충족했다.
- [ ] 프로젝트 핵심 원칙을 훼손하지 않았다.
- [ ] 출처와 확인일을 기록했다.
- [ ] 실제 개인정보·비밀·라이선스 문서가 없다.
- [ ] 자동판정과 사람판단이 분리돼 있다.
- [ ] 코드·문서·샘플·테스트가 일치한다.
- [ ] 관련 문서와 의사결정 기록을 갱신했다.
- [ ] 검증 명령과 결과를 PR에 남겼다.
- [ ] 다음 작업자가 이해할 인수인계가 있다.

## 15. AI용 프로젝트 컨텍스트 요약

JY그룹은 홀딩스, 산업, 서비스와 외부 고객센터로 구성된 가상 조직이다. 대표 문제는 취약한 공통 관리서버와 자회사 시스템 사이 불필요한 연결, 공동 관리자·휴면 수탁사 계정, 과도한 DB 접근, 로그와 자회사 감독 부족이다. 프로젝트의 가치는 취약점을 찾는 것보다 그룹 차원의 개인정보 처리 책임과 신뢰경계를 진단하고, 기술 증적수집으로 반복심사의 효율을 높인 뒤, 개선과 재점검을 통해 위험감소를 입증하는 데 있다.
