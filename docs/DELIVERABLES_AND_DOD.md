# 산출물 및 완료조건

## 1. 목적

완료의 기준을 파일 존재 여부가 아니라 품질, 추적성, 재현성과 공개 안전성으로 정의한다. 모든 산출물은 가상 JY그룹만 다루며 실제 개인정보를 포함하지 않는다.

## 2. 단계별 산출물

| 단계 | 필수 산출물 | 권장 형식 | 완료조건 요약 |
|---|---|---|---|
| 사건조사 | 사건분석, 제도동향, 출처대장 | Markdown/CSV | 공식출처, 사실·해석 분리, 확인일 |
| 범위설계 | 착수계획, 범위서, 조직·업무도, 인터뷰 질문 | Markdown/Drawio | 포함·제외·가정·표본 명시 |
| 현황파악 | 처리현황, 자산대장, 데이터 흐름도, 연결대장 | CSV/XLSX/Diagram | 소유자와 관계키, 누락 검토 |
| 기준매핑 | 통제 매트릭스, 증적요청목록, 체크리스트 | YAML/CSV/XLSX | 기준 성격·버전·판단방법 구분 |
| 사전심사 | 인터뷰 기록, 증적 인덱스, 발견사항 초안 | Markdown/CSV | 사실·증적·기준 추적 가능 |
| 랩 | 개선 전후 구성, 시드 문제, 재현절차 | Compose/YAML/Diagram | 로컬 재현, 외부 공격 불가 |
| 자동수집 | 수집기, 스키마, 테스트, 샘플 결과 | Python/JSON/CSV | 오류·마스킹·반복실행 검증 |
| 위험개선 | 위험대장, 조치계획, 예외·잔여위험 | XLSX/Markdown | 소유자·기한·검증방법 존재 |
| 재점검 | 전후 비교, 발견사항 종료표 | CSV/XLSX | 같은 통제·자산 기준 비교 |
| 최종보고 | 기술보고, CPO 요약, 발표자료, 회고 | MD/DOCX/PPTX/PDF | 독자별 분리, 링크·수치 일치 |

## 3. 필수 문서 세트

### 프로젝트 거버넌스

- README와 통합 수행계획
- Git 작업규정과 AI 작업지침
- 도구·비용표
- 의사결정 기록
- 변경이력과 Release notes

### 컨설팅 작업지

- 사건 및 정책동향 분석서
- 진단범위 정의서
- 개인정보 처리업무 현황표
- 정보자산·개인정보 자산대장
- 개인정보 흐름도와 시스템 연결도
- 본사·자회사·수탁사 RACI
- 증적요청목록과 인터뷰 질문지
- 통합 통제 매트릭스와 점검표
- 발견사항 및 위험대장
- 개선계획과 재점검표

### 기술 결과

- 개선 전/후 랩 구성
- 증적수집기 소스와 사용법
- 출력 JSON Schema 또는 동등한 명세
- 단위·통합·마스킹 테스트
- 합성된 샘플 증적과 생성방법
- 보고서 생성기와 템플릿

### 최종 포트폴리오

- 상세 기술·관리체계 진단보고서
- 2페이지 안팎 CPO/경영진 요약
- 10~15장 면접 발표자료
- 프로젝트 회고와 한계
- 공개용 데모 실행절차

## 4. 산출물 공통 완료조건

모든 문서·데이터·코드는 다음을 만족한다.

- 목적, 범위, 작성일, 버전과 작성자가 식별된다.
- 근거와 출처가 연결된다.
- 가정, 표본과 확인하지 못한 내용이 표시된다.
- 실제 개인정보·비밀·라이선스 제한 자료가 없다.
- 관련 Issue, PR과 Release에서 변경이 추적된다.
- 다른 사람이 README만 보고 재현하거나 검토할 수 있다.
- 링크·용어·ID·수치가 다른 산출물과 일치한다.

## 5. 자동수집기 완료조건

- [ ] 지원 OS·권한·범위와 비지원 항목이 문서화돼 있다.
- [ ] 자산 ID와 실행 메타데이터가 모든 결과에 있다.
- [ ] 읽기 전용 수집을 기본으로 한다.
- [ ] 명령 실패, 권한 부족, 미지원과 시간초과를 구분한다.
- [ ] 비밀번호·토큰·개인정보 값이 수집되지 않거나 마스킹된다.
- [ ] 자동 상태는 세 가지 허용값만 사용한다.
- [ ] 원본 참조와 정규화 결과의 추적성이 있다.
- [ ] 단위·오류·마스킹·샘플 통합 테스트가 통과한다.
- [ ] 같은 대상 재실행 시 의미 없는 차이가 최소화된다.
- [ ] 수집기가 통제를 공식 판정한다는 표현이 없다.

## 6. 발견사항 완료조건

발견은 다음 필드가 채워져야 `확정`된다.

- 고유 ID와 제목
- 적용 회사·업무·자산·표본
- 관찰 사실과 수집일
- 충분한 증적 참조
- 법률·ISMS-P·내부통제 또는 기술기준
- 현실적인 위험 시나리오
- 영향·가능성 및 등급 근거
- 실행 가능한 개선안
- 소유자, 우선순위와 기한
- 예외·잔여위험 처리

발견은 개선 후 동일 기준으로 재확인되고, `해결`, `부분 해결`, `미해결`, `위험 수용` 중 사람이 상태를 정해야 종료된다.

## 7. 전후 비교 완료조건

- 동일한 자산 ID와 통제 ID를 사용한다.
- 수집기 버전이 다르면 결과 영향이 설명돼 있다.
- 변경한 설정, 승인자, 변경일과 롤백 방법이 있다.
- 개선 전/후 증적 참조와 해시가 있다.
- 기능·업무 영향과 새로운 위험을 확인한다.
- 잔여위험 및 후속 검토일이 있다.

## 8. 경영진 보고 완료조건

경영진 보고는 기술 항목 나열이 아니라 다음 의사결정을 돕는다.

- 현재 가장 중요한 3~5개 그룹 개인정보 위험
- 사고 발생 시 정보주체·업무·법률·평판 영향
- 자회사·수탁사·계열사 연결에서 책임지는 주체
- 즉시 조치와 30/90일·중장기 계획
- 필요한 예산·인력·정책 결정
- 개선된 위험과 남은 위험
- CPO가 다음에 보고할 시점과 지표

기술보고와 숫자·Finding ID가 일치해야 한다.

## 9. 공개용 저장소 완료조건

- [ ] `main`은 재현 가능한 최종 상태다.
- [ ] README가 의도, 사건, 방법, 결과와 한계를 설명한다.
- [ ] 설치·실행·테스트·데모 명령이 검증됐다.
- [ ] 합성 데이터 생성 근거가 있다.
- [ ] gitleaks 및 품질검사가 통과한다.
- [ ] 대용량·원본·비공개 증적이 제거됐다.
- [ ] 제3자 문서의 저작권과 라이선스를 침해하지 않는다.
- [ ] 미완료·제외 범위를 숨기지 않는다.
- [ ] `v1.0-final` Release에 핵심 결과와 한계가 있다.

## 10. 100시간 범위 보호

다음 기능은 핵심 산출물에 직접 필요할 때만 포함한다.

- 웹 대시보드
- 다중 클라우드 점검
- 복잡한 에이전트 배포
- 상용 보고서 수준 UI
- 실제 공격 익스플로잇
- 모든 OS·DB 지원

시간이 부족하면 UI와 지원플랫폼을 줄이고 자산·흐름·통제 매핑, 발견의 질, 전후 증적과 최종 보고를 보존한다.
