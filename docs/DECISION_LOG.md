# 의사결정 기록

## 사용법

범위, 기술, 비용, 기준, 보안 또는 산출물에 영향을 주는 결정을 기록한다. 기존 결정을 변경할 때 원문을 지우지 않고 새 Decision ID에서 대체 관계를 표시한다.

필드: `ID / 날짜 / 상태 / 결정 / 이유 / 검토한 대안 / 영향 / 재검토 조건`

## 확정된 결정

### ADR-001: 기본 프로젝트 주제

- 날짜: 2026-08-28
- 상태: 확정
- 결정: HD현대그룹 계열사 개인정보 유출사고에서 착안한 가상 그룹사 개인정보 보호 관리체계 진단 및 ISMS-P 사전심사를 기본 프로젝트로 한다.
- 이유: 실제 개인정보 컨설팅의 자회사 점검, 관리체계, 인증준비와 기술점검을 하나의 서사로 연결한다.
- 대안: 단일 진단 스크립트, 클라우드 점검, 웹 취약점 자동화.
- 영향: 기능보다 처리현황·책임·증적·개선·보고의 전체 흐름을 우선한다.

### ADR-002: 증적 자동수집 결합

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 별도 아이디어였던 증적 자동수집 기능을 기본 프로젝트에 제한적으로 결합한다.
- 이유: 심사준비 실무의 반복작업을 줄이고 개선 전후를 같은 기준으로 입증할 수 있다.
- 대안: 전부 수작업, 자동 적합성 판정 도구.
- 영향: 수집기는 판정을 대체하지 않고 `확인 필요/개선 후보/자동수집 불가`만 출력한다.

### ADR-003: 최소비용 구성

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 필수 신규비용 0원을 목표로 VS Code, GitHub Free, VMware, Ubuntu, Kali, Docker와 오픈소스를 사용한다.
- 이유: 개인 100시간 프로젝트에서 비용보다 재현성과 컨설팅 결과에 집중한다.
- 대안: 클라우드 랩, 상용 스캐너, GitHub Team.
- 영향: 클라우드 비용과 상용도구 종속성을 배제한다.

### ADR-004: Microsoft 365 활용

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 사용자가 보유한 Microsoft 365를 Excel 대장, Word 보고서와 PowerPoint 발표에 활용한다.
- 이유: 현업 산출물 형식과 친숙하며 추가비용이 없다.
- 영향: 핵심 원천데이터는 CSV/YAML/Markdown으로도 관리해 Git diff와 재생성을 보장한다.

### ADR-005: Git 브랜치 구조

- 날짜: 2026-08-28
- 상태: 대체됨 → ADR-009
- 결정: `main`, `develop`과 9개 규정 작업 브랜치를 사용하며 Issue→Branch→Commit→PR→Review→Merge→Tag 흐름을 따른다.
- 이유: 수행과정을 포트폴리오 증적으로 남기고 향후 GPT 작업을 통제한다.
- 영향: 직접 push를 금지하고 모든 작업을 Issue/PR에 연결한다.

### ADR-006: 기준의 역할 구분

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 개인정보 보호법과 ISMS-P를 중심으로 하고 ISO/IEC 27701은 공개·합법적 자료 범위의 관리체계 참고, 주통기 가이드는 기술점검 보조에만 사용한다.
- 이유: 서로 다른 기준의 법적·심사상 성격을 과장하지 않는다.
- 영향: 공식 인증·법률준수·기반시설 판정 표현을 금지한다.

### ADR-007: 데이터 안전

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 합성 데이터만 사용하고 원본 민감증적, 인증정보, 실제 개인정보와 ISO 유료 원문을 Git에 저장하지 않는다.
- 이유: 공개 포트폴리오의 안전·윤리·저작권을 보장한다.
- 영향: 공개 증적은 마스킹·요약본과 해시만 제공한다.

### ADR-008: 저장소 공개 시점

- 날짜: 2026-08-28
- 상태: 확정
- 결정: 진행 중에는 Private로 운영하고 최종 정제와 비밀검사 후 Public 전환을 검토한다.
- 이유: 초안 증적과 설정이 의도치 않게 공개되는 것을 방지한다.
- 영향: v1.0 전 공개 점검 체크리스트가 필수다.

### ADR-009: 실습 Git 브랜치 (ADR-005 대체)

- 날짜: 2026-10-07
- 상태: 확정
- 결정: 현재 작업은 `feat/linux-evidence-collector`에 직접 커밋·푸시한다. Cursor 원격은 `git pull`하지 않는다. `main` 머지·PR은 나중에 한다.
- 이유: 수행자 GitHub와 에이전트 원가가 다르고, 조각마다 로컬에 파일을 복사해 올리는 흐름이다.
- 대안: ADR-005대로 Issue/PR만 사용.
- 영향: README를 에이전트 원고로 통째 덮어쓰지 않는다. 복구 커밋 `20a5e03`.
- 재검토 조건: Gitleaks 후 Public/PR를 열 때 ADR-005 흐름으로 돌아갈 수 있다.
- 대체: ADR-005

### ADR-011: 시험 후 즉시 개선과 Checks 유지

- 날짜: 2026-10-06
- 상태: 확정
- 결정: F-01~F-02는 비활성·그룹·비공유로 바로 고친다. 재점검이 적합이어도 C02·C03·C04·D02는 `미흡`으로 둔다.
- 이유: 가이드 9.2. 초기 미흡을 적합으로 덮지 않음.
- 영향: R-01·R-02a·R-02b 적합. Findings 위험점수 열(3)은 덮지 않고 14장에서 1–3×1–3으로 분해.

### ADR-012: F-03 잔존 증적 유지

- 날짜: 2026-10-06
- 상태: 확정
- 결정: T12(id=14)는 삭제하지 않는다. T15·조직도 삭제하지 않는다. C01 자료 보안은 미리보기 T01·T11만.
- 이유: 참조 잔존을 보여야 하고, Scheduler 미리보기 없이 삭제하면 증적이 사라진다.
- 영향: E02 적합, E03·D03·R-03 미흡, A-03/CR-04 예정.

### ADR-013: 사본·diff는 Git 밖

- 날짜: 2026-10-07
- 상태: 확정
- 결정: `jy-doc02-copy.txt`, `users-*.json`, PNG, 토큰을 Git에 넣지 않는다. tickets.csv는 관측된 id만 기입하고 T03~T10·T13·T14는 공란.
- 이유: ADR-007. 추측 기입 금지.
- 영향: Evidence JSON-F01-DIFF·E-D03-A01. 해시는 로컬 Get-FileHash.

### ADR-014: 미확인·적용 제외·미발송

- 날짜: 2026-10-07
- 상태: 확정
- 결정: B04·E04는 `미확인`, F03은 `적용 제외`. 모의 통지문은 보내지 않는다. Controls 항·호는 원문 전 공란.
- 이유: 메일·백업 실측·AI 연결·조문 원문을 하지 않은 것을 적합으로 쓰지 않음.
- 영향: 16~17장 문서. 실제 신고 없음.
