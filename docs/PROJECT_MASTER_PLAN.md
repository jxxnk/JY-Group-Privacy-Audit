# 프로젝트 통합 수행계획

## 1. 문서 목적

이 문서는 JY Group Privacy Audit의 단일 수행 기준서다. 프로젝트를 처음 보는 사람이나 AI도 README와 이 문서를 읽으면 배경, 고객사 가정, 수행 순서, 판단 원칙과 최종 산출물을 이해할 수 있어야 한다. 실제 작업 중 범위·일정·산출물이 바뀌면 Issue와 의사결정 기록을 먼저 남기고 이 문서를 갱신한다.

## 2. 프로젝트 한 문장 정의

HD현대그룹 계열사 개인정보 유출사고에서 드러난 계열사 간 신뢰경계와 연결관리 문제를 가상의 JY그룹에 재현하고, 개인정보 보호법·ISMS-P 중심의 관리체계 진단과 제한적인 기술 증적 자동수집을 결합해 개선 전후를 입증하는 100시간짜리 개인정보 보호 컨설팅 포트폴리오다.

## 3. 출발 사건과 문제의식

공개된 HD현대그룹 사고에서는 HD한국조선해양 MDM 서버의 파일 업로드 취약점이 침입에 악용됐고, 업무상 불필요한 계열사 시스템 연결이 공격 확산 경로가 됐다. 프로젝트는 특정 기업의 미공개 사실을 추정하지 않고 개인정보보호위원회 공개자료에 확인된 사실만 사용한다.

여기서 얻은 핵심 문제의식은 다음과 같다.

1. 취약점 한 개의 제거만으로 그룹 차원의 위험이 해소되는가?
2. 계열사별 관리체계가 존재해도 회사 사이의 연결과 책임은 누가 검토하는가?
3. 개인정보 처리방침·위수탁 계약·자산대장과 실제 접근권한 및 네트워크 연결은 일치하는가?
4. 기술 결과를 법률·인증 요구사항과 연결하되 과도한 자동판정을 막을 수 있는가?
5. CPO와 경영진이 사고 전 위험을 인지하고 우선순위를 결정할 증적이 있는가?

## 4. 가상 컨설팅 의뢰

JY홀딩스 CPO는 그룹사 간 시스템 연결과 자회사·수탁사 관리 수준을 확인하고, 향후 강화될 개인정보 보호 책임 및 ISMS-P 요구에 대비하고자 사전진단을 의뢰했다. 컨설턴트는 다음 과업을 수행한다.

- 그룹 개인정보 처리업무 및 관련 자산 식별
- 본사·자회사·수탁사 간 데이터 흐름과 책임 분석
- 처리방침·내부규정·계약·운영현황 간 일관성 점검
- 계정·권한·네트워크·서버·DB·로그에 대한 표본 기술점검
- 반복 가능한 증적수집 도구 제작
- 위험평가, 개선 로드맵, 재점검과 경영진 보고

## 6. 핵심 가설

- 계열사별 자산대장을 합치는 것만으로는 그룹사 간 연결 위험을 찾기 어렵다.
- 개인정보 흐름도와 시스템 연결도를 함께 비교해야 책임 공백이 드러난다.
- 위수탁 계약의 문구보다 수탁사 계정의 실제 권한과 접속기록을 확인해야 한다.
- 자동화는 수집 일관성과 재점검 효율을 높이지만 업무상 필요성과 법적 적합성을 판단할 수 없다.
- 경영진 보고에는 취약점 개수보다 영향받는 정보주체, 확산 가능성, 법적 영향, 개선비용과 기한이 중요하다.

## 7. 수행 원칙

1. 모든 데이터와 조직은 가상으로 구성한다.
2. 사건 사실과 법령·공식 기준은 출처와 확인일을 남긴다.
3. 공개 가이드의 적용범위와 법적 효력을 과장하지 않는다.
4. 주통기 가이드는 기술점검 보조기준으로만 사용한다.
5. ISO 원문을 합법적으로 확보하지 않은 경우 공식 적합성 판정을 하지 않는다.
6. 자동화 결과와 컨설턴트 최종판단을 구분한다.
7. 발견사항은 반드시 증적, 위험 시나리오, 기준, 개선안과 재점검 결과로 연결한다.
8. 개인정보와 비밀정보는 Git에 넣지 않는다.

## 9. 단계별 상세 수행방법

### 9.1 사건·제도 조사

- 공식 보도자료에서 사고 경로, 유출대상, 제재 사유와 개선 요구를 추출한다.
- 언론 보도는 보조자료로만 사용하며 공식자료와 불일치하면 공식자료를 우선한다.
- 시행 중인 법과 공포 후 시행예정 내용을 구분한다.
- ISO/IEC 27701:2025의 독립 PIMS 방향, ISMS-P 의무 확대 방향과 CPO 책임 강화가 프로젝트에 미치는 영향을 기록한다.
- 조사시점 이후 변경 가능성이 높은 내용에는 `최종 확인일`을 표시한다.

### 9.2 범위 및 인터뷰 설계

- 개인정보 처리업무를 조직도가 아니라 업무목적으로 구분한다.
- 각 처리업무에 정보주체, 항목, 목적, 법적 근거, 수집경로, 보유기간, 파기방법, 시스템, 제공·위탁 관계와 책임자를 연결한다.
- CPO, IT운영자, 자회사 담당자, 수탁사 관리자용 질문지를 구분한다.
- 표본선정 이유와 한계를 기록한다.

### 9.3 현황 분석

- 개인정보 자산대장과 서버·DB·네트워크 자산대장을 별도로 작성한 뒤 관계키로 연결한다.
- 데이터 흐름도는 수집→이용→제공/위탁→보관→파기 생명주기를 나타낸다.
- 시스템 연결도는 존, 소유회사, 출발지, 목적지, 포트, 업무목적, 승인자, 만료일을 표시한다.
- 문서상 흐름과 실제 연결이 다르면 발견 후보로 등록한다.

### 9.4 통제 매핑

하나의 발견을 여러 기준에 중복 복사하지 않고 통합 통제 ID를 만든다. 예를 들어 `AC-03 관리자 최소권한`에 법 제29조, ISMS-P 접근통제 항목, ISO 참고원칙과 주통기 계정관리 점검항목을 연결한다. 각 기준의 성격은 `법적 의무`, `인증 심사기준`, `관리체계 참고`, `기술 확인방법`으로 구분한다.

### 9.5 사전심사

증적 요청 → 인터뷰 → 문서 검토 → 기술 표본 확인 → 상충사항 질문 → 발견 확정 순으로 수행한다. 증적이 없다는 사실과 통제가 없다는 판단은 같지 않으므로 추가 확인 여부를 남긴다.

### 9.6 기술 랩

로컬 VMware 또는 Docker 네트워크에 홀딩스 관리존, 산업 HR존, 서비스 고객존, 수탁사 접근존을 구성한다. 개선 전 환경에는 불필요한 연결, 공동 관리자, 휴면계정, 넓은 DB 바인딩, 부족한 로그 등 사전에 정의한 문제만 넣는다. 실제 악성코드, 인터넷 대상 스캔, 공격 자동화는 포함하지 않는다.

### 9.7 증적수집기

수집기는 읽기 전용 명령을 우선하며 자산별 JSON 원본, 정규화 결과, 실행 로그와 해시를 생성한다. 비밀번호·토큰·개인정보 값은 수집하지 않거나 마스킹한다. 점검은 계정, 권한, 서비스, 포트, 방화벽, 패치, 로그, 백업, DB 접근 및 시스템 간 도달성으로 모듈화한다.

### 9.8 위험평가와 개선

위험도는 법적 영향, 정보주체 영향, 공격 확산성, 노출범위, 통제성숙도와 발생가능성을 근거로 산정한다. 숫자만 제시하지 않고 왜 해당 등급인지 서술한다. 개선안은 즉시 차단/30일/90일/중장기로 나누고 소유자, 선행조건, 검증방법과 잔여위험을 둔다.

### 9.9 재점검과 보고

개선 전과 동일한 수집기 버전 또는 변경이력이 명확한 버전으로 재점검한다. 기술팀에는 명령·설정·재현방법을, CPO와 경영진에는 사고 시나리오·영향·우선순위·의사결정 사항을 제공한다.

## 10. 핵심 시나리오

대표 위험 시나리오는 `JY홀딩스 관리 서버 침해 → 불필요한 계열사 연결 이용 → JY산업 HR 시스템 접근 → 공동관리자 또는 과도권한 악용 → 개인정보 조회·반출 → 탐지 지연`이다. 이 시나리오를 다음 통제들이 끊는지 확인한다.

- 연결 승인, 만료와 정기검토
- 네트워크 분리 및 기본거부
- 고유 관리자 계정과 MFA
- 수탁사·협력사 계정 생명주기
- 개인정보 조회 최소권한
- 접속·조회·반출 로그와 이상징후 탐지
- 그룹 CPO 보고 및 사고대응

## 11. 발견사항 표준 구조

각 발견은 다음 필드를 가진다.

| 필드 | 내용 |
|---|---|
| Finding ID | 예: `F-AC-001` |
| 제목 | 사실을 드러내는 간결한 제목 |
| 범위/자산 | 회사, 시스템, 업무와 표본 |
| 관찰 사실 | 해석 전 확인된 현재 상태 |
| 증적 | 파일, 명령결과, 인터뷰와 수집시각 |
| 기준 | 통합 통제 ID와 관련 근거 |
| 위험 시나리오 | 위협→취약상태→영향 |
| 영향/가능성 | 등급과 구체적 근거 |
| 권고안 | 기술·절차·책임 개선 |
| 소유자/기한 | 이행 책임과 목표일 |
| 예외/잔여위험 | 수용 사유와 승인자 |
| 재점검 | 방법, 결과, 증적과 일자 |

## 12. 성공지표

- 개인정보 처리업무 100%가 자산·책임자·보유기간과 연결된다.
- 그룹사 간 연결 100%에 업무목적·승인자·검토일이 있거나 발견으로 등록된다.
- 관리자 및 수탁사 표본계정 100%에 소유자와 필요성이 확인된다.
- 발견사항 100%가 증적·기준·개선·재점검에 추적된다.
- 자동수집 항목 100%가 사람이 최종판단하도록 설계된다.
- 고위험 발견은 개선되거나 경영진이 잔여위험을 명시적으로 승인한다.
- 저장소 비밀검사와 테스트가 통과한다.

## 13. 한계와 정직한 표현

이 결과는 교육용 가상환경의 사전진단이며 실제 인증, 법률자문 또는 특정 기업에 대한 감사결론이 아니다. ISO 전체 원문을 보유하지 않았다면 `ISO/IEC 27701 공개정보 및 원칙 참고`라고 표현한다. 자동수집되지 않은 통제는 미흡이 아니라 `자동수집 불가/인터뷰 및 문서 확인 필요`로 둔다.

## 14. 최종 포트폴리오 이야기

최종 결과는 사건 요약에서 끝나지 않는다. 사건에서 신뢰경계 문제를 발견하고, 이를 가상 고객사의 처리업무·연결·책임으로 모델링하고, 법률과 인증기준으로 진단하며, 자동수집으로 증적 준비를 효율화하고, 개선 후 같은 기준으로 위험 감소를 입증하는 일관된 서사를 보여준다. Git 이력은 그 판단이 어떤 질문과 검토를 거쳐 발전했는지 증명한다.
