# 법률·인증·기술 통제 기준

## 1. 목적과 기준일

이 문서는 JY그룹 사전진단에서 기준을 어떻게 구분하고 연결할지 정한다. 법률·정책·인증자료는 바뀔 수 있으므로 실제 분석 시 공식 원문을 다시 확인한다. 초기 기획 기준일은 **2026-08-28**이다.

이 문서는 법률자문이나 공식 인증 체크리스트를 대체하지 않는다.

## 2. 기준의 우선순위와 역할

| 계층 | 기준 | 프로젝트 역할 |
|---|---|---|
| 법적 의무 | 개인정보 보호법 및 하위법령·고시 | 처리 적법성, 권리, 안전조치, 책임과 사고대응 판단의 중심 |
| 국내 인증 | ISMS-P 인증기준 및 세부점검항목 | 관리체계·보호대책·개인정보 처리단계의 사전심사 구조 |
| 국제 참고 | ISO/IEC 27701:2025 공개정보·합법적 열람자료 | PIMS 책임, 역할, 위험과 지속개선 관점 보강 |
| 기술 확인 | 2025 주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드 | 서버·DB·네트워크 설정의 증적수집 방법 보조 |
| 내부 기준 | JY그룹 가상 정책·표준·계약 | 더 엄격한 조직 요구와 실제 운영 일치성 확인 |

한 기준이 다른 기준을 자동으로 충족시키지 않는다. 예를 들어 주통기 항목이 양호해도 개인정보 보호법상 안전조치 의무가 전부 충족됐다고 판정하지 않는다.

## 3. 개인정보 보호법 핵심 주제

| 조항/주제 | 프로젝트 확인 질문 | 대표 증적 |
|---|---|---|
| 제15조 수집·이용 | 처리 목적별 적법근거가 있는가? 최소항목인가? | 동의서, 신청화면, 처리현황표, 법적근거 |
| 제18조 목적 외 이용·제공 제한 | 당초 목적 외 이용·제공을 통제하고 기록하는가? | 제공대장, 승인기록, 예외근거 |
| 제21조 파기 | 보유기간 종료 후 지체 없이 파기하는가? 분리보관이 필요한가? | 보유기간표, 배치로그, 파기대장, 백업정책 |
| 제26조 업무위탁 | 수탁자 공개·계약·교육·감독·재위탁 통제가 있는가? | 계약서, 처리방침, 점검표, 교육·개선 증적 |
| 제29조 안전조치 | 위험에 맞는 관리·기술·물리적 조치를 하는가? | 내부계획, 권한, 로그, 암호화, 네트워크 설정 |
| 제30조 처리방침 | 공개 내용이 이해 가능하고 실제 처리와 일치하는가? | 처리방침 버전, 처리현황 비교표, 변경검토 |
| 제31조 보호책임자 | CPO 권한·독립성·보고와 지원이 실질적인가? | 지정문서, 직무기술서, 경영진 보고, 예산·회의록 |
| 제34조 유출 통지·신고 | 탐지, 판단, 통지·신고와 정보주체 보호 절차가 있는가? | 대응절차, 연락망, 훈련, 사고판단 기록 |
| 정보주체 권리 | 열람·정정·삭제·처리정지 요청을 기한 내 처리하는가? | 요청대장, 인증절차, 처리기록, 거절근거 |

세부 의무는 시행령, 안전성 확보조치 기준, 고시와 적용대상에 따라 달라질 수 있다. 통제 매핑 시 조문 제목만 연결하지 말고 최신 원문과 사실관계를 함께 확인한다.

## 4. 미래 방향 반영

2026년 공개된 제도 변화 방향 중 프로젝트에 반영할 주제는 다음과 같다.

- CEO와 CPO의 실질적인 개인정보 보호 책임 및 내부관리 강화
- 사고 발생 후 대응뿐 아니라 유출 가능성의 조기 식별과 예방
- 허위·훼손 및 사고대응 책임 강화 방향
- 일정 규모·성격의 주요 기업·기관에 대한 ISMS-P 의무 확대 방향
- 처리방침 평가, 정보주체가 이해하기 쉬운 고지와 실제 운영 일치성 강화
- 공급망·수탁사·계열사 연결을 포함한 책임 추적성

시행 전 제도는 `향후 대비 통제`로 별도 표시하며 현재 위법 또는 의무라고 단정하지 않는다. 시행일·대상범위가 확정되지 않았거나 바뀔 수 있는 내용은 공식 원문 확인 후 갱신한다.

## 5. ISMS-P 적용 방식

프로젝트는 ISMS-P의 큰 구조를 이용해 사전심사를 구성한다.

1. 관리체계 수립 및 운영
2. 보호대책 요구사항
3. 개인정보 처리단계별 요구사항

각 점검항목에는 다음을 기록한다.

- 통제 ID와 공식 항목명/버전
- 적용 회사·업무·시스템
- 인터뷰 질문
- 요청 증적
- 기술 확인방법
- 확인 사실
- 컨설턴트 판단 및 근거
- 발견 ID와 개선상태

인증대상 범위 확정, 실제 심사원 판단과 결함보고서 발행을 흉내 내어 공식 인증결과처럼 제시하지 않는다. 결과명은 `ISMS-P 준비수준 사전진단`으로 한다.

## 6. ISO/IEC 27701:2025 적용 방식

ISO/IEC 27701:2025는 개인정보 정보관리체계(PIMS)의 국제적 관점을 보강한다. 프로젝트는 특히 다음 주제를 참고한다.

- PII controller와 PII processor의 역할·책임
- 개인정보 관련 위험평가 및 처리
- 정책, 역량, 운영통제와 성과평가
- 공급자·수탁자 관계와 책임
- 정보주체 권리 및 개인정보 생명주기
- 모니터링, 내부검토와 지속개선

공식 표준 전체를 합법적으로 열람하지 않은 상태에서는 세부 조항번호를 추정하거나 완전한 갭분석을 주장하지 않는다. ISO 원문과 표·부속서를 저장소에 커밋하지 않는다. 향후 원문 열람권을 확보하면 별도 Issue에서 통제 매핑을 재검토한다.

ISO 공식 개요: [ISO/IEC 27701:2025](https://www.iso.org/standard/27701)

## 7. 주통기 가이드 적용 경계

2025년 주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드는 다음 영역의 확인방법을 설계할 때만 사용한다.

- Unix/Linux·Windows 계정 및 권한
- 불필요 서비스, 포트와 네트워크 접근통제
- 파일·디렉터리 권한과 중요 설정
- 패치 및 보안설정
- DB 계정·원격접속·권한
- 로그 설정과 보관
- 네트워크 장비의 접근·인증·관리 설정

적용하지 않는 영역:

- 개인정보 수집의 적법성
- 동의서와 처리방침의 적정성
- 위수탁 법적 책임 판정
- 정보주체 권리 처리
- CPO 독립성과 경영진 책임의 최종판단
- JY그룹을 실제 주요정보통신기반시설로 분류하는 표현

KISA 자료: [2025년 주요정보통신기반시설 기술적 취약점 분석·평가 상세가이드](https://www.kisa.or.kr/2060204/form?page=1&postSeq=22)

## 8. 통합 매핑 모델

매핑 파일은 다음 필드를 갖는다.

| 필드 | 설명 |
|---|---|
| `control_id` | 내부 통합 통제 ID |
| `title` | 통제 목적 중심 이름 |
| `risk_statement` | 통제가 없을 때 발생할 위험 |
| `pipa_refs` | 최신 법령 근거 |
| `ismsp_refs` | 공식 기준 버전과 항목 |
| `iso_reference` | 공개정보/합법적 자료의 참고 주제 |
| `critical_guide_refs` | 기술항목과 적용 플랫폼 |
| `evidence_required` | 문서·인터뷰·기술 증적 |
| `automatable` | yes/partial/no |
| `human_judgment` | 사람이 확인할 맥락 |
| `owner` | 통제 소유자 |

### 예시

`NET-02 계열사 간 연결 승인 및 최소화`는 법 제29조 관련 안전조치, ISMS-P 네트워크 접근통제, ISO의 위험·공급망/조직관계 관점과 주통기 네트워크 접근통제 확인방법을 연결한다. 자동화는 현재 도달성과 방화벽 규칙을 수집할 뿐 `업무상 필요한 연결인지`는 승인서·인터뷰를 본 사람이 결정한다.

## 9. 핵심 통제 도메인

- `GOV`: 거버넌스, CPO, 정책과 보고
- `INV`: 개인정보 처리업무·자산·흐름
- `LAW`: 적법성, 고지, 동의와 권리
- `TPR`: 자회사·수탁사·제3자 관리
- `IAM`: 계정, 인증, 권한과 검토
- `NET`: 신뢰경계, 연결, 분리와 원격접속
- `SYS`: 서버·DB 설정, 패치와 악성코드 방어
- `LOG`: 접속기록, 탐지와 모니터링
- `LIFE`: 보유, 파기, 백업과 복구
- `IR`: 유출 대응, 통지·신고와 훈련
- `ASSURE`: 내부점검, 증적, 개선과 재점검

## 10. 증적과 판단의 연결

증적 한 개가 통제 전체를 입증하지 않을 수 있다. 예를 들어 방화벽 규칙은 기술적 연결을 보여주지만 승인·정기검토·업무목적까지 증명하지 않는다. 따라서 각 통제는 `문서`, `인터뷰`, `기술`, `관찰` 증적의 조합과 충분성 조건을 정의한다.

증적이 없을 때는 다음 중 하나로 기록한다.

- 통제가 없음을 관계자가 확인함
- 통제는 주장되나 증적 미제출
- 표본 또는 권한 한계로 확인 불가
- 자동수집 대상이 아님

법·인증·가이드 변경이 발견되면 별도 Issue에서 이전 버전과 새 버전의 시행일, 대상, 통제·코드·보고서 영향을 비교한다. 변경은 `docs/control-mapping` 또는 후속 `docs/*` 브랜치에서 반영하고 의사결정 기록과 출처 확인일을 갱신한다.
